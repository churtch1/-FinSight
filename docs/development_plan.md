# 分阶段开发计划

## 第一阶段：设计数据库和统一资产模型

目标：先把数据底座定稳，不急着大规模写功能代码。

交付物：

- 统一资产模型文档。
- 数据库表设计文档。
- 目标项目目录结构。
- 明确各阶段边界。

验收标准：

- IBKR、HSBC PDF、招商银行 PDF、CSV 都能映射到同一套标准模型。
- 数据库表能支持当前持仓、交易、现金流、收益、快照和导入审计。
- 后续代码实现有清晰目录边界。

## 第二阶段：实现 Supabase 连接

目标：让本地采集端能稳定写入云数据库，让 Dashboard 能只读查询。

任务：

- 整理 `db.py`。
- 拆分 Supabase writer / repositories。
- 完善导入记录与错误记录。
- 更新 `sql/schema.sql`。
- 增加 `views.sql` 和 `policies.sql`。

验收标准：

- 本地脚本可以写入账户、标的、持仓、交易、现金流。
- Dashboard 可以只读查询。
- service role key 只在本地 `.env` 使用。

## 第三阶段：实现 IBKR 数据同步

目标：稳定采集 IBKR 数据。

任务：

- 连接 IB Gateway / TWS。
- 获取账户列表。
- 获取当前持仓。
- 获取多币种现金。
- 获取账户摘要。
- 获取可用交易记录。
- 标准化为统一模型。
- 写入 Supabase。

验收标准：

- `sync_ibkr.py` 可以完成一次同步。
- Supabase 出现 IBKR 账户、持仓、现金。
- 同步失败时有明确错误记录。

## 第四阶段：实现 PDF 上传与解析框架

目标：建立可扩展 parser 框架，而不是只写一个银行的临时代码。

任务：

- 新增 `BasePdfParser`。
- 实现 HSBC 中国 parser。
- 实现招商银行 parser。
- 支持 parser 返回置信度与待复核字段。
- 无法识别的数据进入 `import_errors`。
- 保留导入文件审计信息。

验收标准：

- `import_pdf.py` 可以自动识别或指定 parser。
- PDF 中现金、基金、理财、债券、股票至少能进入标准模型。
- 解析失败不阻塞整个导入。

## 第五阶段：做手机端 Streamlit 看板

目标：先做一个手机上能舒服查看的看板。

页面模块：

- 总资产。
- 今日变化或最近同步时间。
- 账户分布。
- 资产类别分布。
- 币种分布。
- 持仓明细。
- 收益概览。
- 最近导入记录。
- 待处理错误。

验收标准：

- 手机浏览器访问可读。
- 无 Supabase 写权限暴露。
- 主要指标首屏可见。

## 第六阶段：增加历史快照和收益分析

目标：从“当前资产”升级到“资产变化与收益”。

任务：

- 生成每日 `portfolio_snapshots`。
- 生成账户、资产类别、币种 breakdown。
- 展示历史净值曲线。
- 计算总收益。
- 初步处理入金出金对收益率的影响。

验收标准：

- 每次同步后可生成快照。
- Dashboard 可以展示历史净值。
- 收益分析不把入金误算为投资收益。

## 第七阶段：优化成更漂亮的网页端

目标：在数据链路稳定后优化体验。

可选方向：

- 继续打磨 Streamlit。
- 或升级为 Next.js + Supabase。

任务：

- 更好的手机 UI。
- 登录与权限。
- 交互图表。
- 持仓搜索。
- 收益归因。
- 异常复核页面。

验收标准：

- 手机体验接近正式产品。
- 数据加载快。
- 权限清晰。
- 易于长期维护。
